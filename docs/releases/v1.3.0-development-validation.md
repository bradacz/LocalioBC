# LocalioBC 1.3.0 (9) release validation

Checked on 15 November 2026 (Europe/Prague). **Direct 1.3.0 (9) is published and verified; Store 1.3.0 (9) is Waiting for Review**, submitted at **04:34 CET** after Transporter delivery at **04:24 CET** and Apple processing. The prior 1.2.1 (7) submission was withdrawn and showed Developer Rejected before replacement. Apple returned 1 Item Submitted for build 9. Store release remains manual after approval; it is not yet publicly available. The owner authorized both channels. Local build 8 artifacts remain unchanged and were never distributed; build 9 aligns the manifest with optional media-upload disclosures.

## Automated checks

The final build 9 direct-target suite passed **58 tests, zero failures and zero skips**, with **zero compiler diagnostics**:

- 30 video-pipeline regression tests.
- 9 updater tests, including deferring checks and installation while uploading.
- 10 upload-coordinator tests: explicit batch start, independent queue persistence, deduplication, ambiguous acknowledgements, bounded retry, cancellation, changed files, re-selection with a new remote path, cooldowns, disk failures and credential recovery.
- 5 URLSession transport tests: request headers, binary file uploads, streaming SHA-256 verification when directory metadata lacks a checksum, cancellation, regional host restrictions, redirects and HTTP 429 handling.
- 4 editor handoff tests: real output files and security-scoped bookmark round trips, merged and separate exports, and preserving completed items after failure/cancellation/editor reset.

All Bunny tests use synthetic credentials and injected storage/transports or URLProtocol responses. No real Bunny upload or real credential write was used to establish these results. Tests never send video files to Localio Labs.

## Native app checks

The actual editor was built and inspected in Czech and English, light and dark appearance, at the default 1180 × 760 window and the supported minimum 1040 × 680 editor content size (approximately 1040 × 712 including native title bar). Representative merged/separate quality, target-size and lossless layouts were inspected. The full export action stayed visible without a vertical export ScrollView.

Native checks included pending crop validation, a rejected 1 MB target on a 120-second clip, progress, completion and the additional Bunny result action. The 1 MB warning and pending-crop explanation were fully readable together at minimum size. An ordinary merged export and a two-clip separate export exercised the finished-file handoff. The launch screen includes the Bunny capability and signup link marked with a smaller “affiliate” label. At the owner's request, the Bunny information sits above the footer with smaller explanatory text and directs users to app Settings; it has no separate setup button.

The real production queue view was additionally compiled in a private, ignored harness with synthetic active/completed/failed transfers to inspect progress, action alignment and error wrapping without using a Bunny account. That harness is not part of either shipping target or the local application preview. A language observation issue found there was corrected in the production queue view.

The universal Store QA build passed strict code-signature checks and contains arm64/x86_64 slices. It has sandbox, user-selected read/write, app-scoped bookmarks and outgoing-network grants. It physically excludes Sparkle, its helpers, linked framework, SU configuration and updater Mach exceptions. The direct development build retains installer integration and disables Downloader XPC because the host now has outgoing-network access.

Runtime checks used Apple Silicon on the available macOS host. No physical Intel or macOS 14 runtime test is claimed. QA builds are ad-hoc signed and use isolated bundle identifiers; they are not notarized distribution artifacts.
